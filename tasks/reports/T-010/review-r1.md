## Implementer assumptions (judged)

1. `website` optional, ≤ 500: **accepted**. It is a honeypot, and the server only checks for a non-empty value.
2. `publishedAt` uses `z.iso.datetime()` (Z only) and `id` uses `z.uuid()` (RFC variant): **accepted**. The server must emit `toISOString()` and `crypto.randomUUID()`, which T-014 will do.
3. `turnstileToken` 1..4096: **accepted**. Cloudflare tokens are ≤ 2048, so this is a generous work bound.
4. An empty name gives `too_short`, an empty email gives only `required`, and email `too_long` + `invalid` can both be returned: **accepted**. This matches the `api.md` table, the "return all" semantics, and the design's `cErrors()` (`trim().length < 2` for the name).
5. Lone CR → LF before trim: **accepted**. Otherwise a bare CR would be a C0 control and fail as `invalid_characters`, which would be hostile to users.
6. U+0142 `ł` has no canonical decomposition, so the test uses `e`+U+0301 and `a`+U+0328: **accepted, and correct**. The task and `testing.md` §3 wording ("decomposed `ł`") is wrong (see notes).
7. `-- --coverage` is ignored: **confirmed** (R1-06).
8. `interface` for `ContactInput`/`ApiSuccess<T>` (lint rule): **accepted**.
