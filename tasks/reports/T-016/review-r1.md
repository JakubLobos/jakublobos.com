## Orchestrator questions

1. **`/set-language` redirect vs 400.** The implementation is correct. `architecture.md` §6, ADR-0007 and `security.md` T13 all say a non-allowlisted `to` redirects 302 to the locale home and only an invalid `lang` gets 400. The spec's `{ cookie, location } | { error: 400 }` fits this: the error branch is for `lang` only.
2. **Single header source.** `security-headers.ts` feeds both `_headers` and the Worker; values match `security.md` §4 exactly; the integration fails the build over 100 rules or 2,000 chars per line. **Header vs meta CSP (ADR-0012):** no conflict. The header carries only `frame-ancestors`/`base-uri`/`form-action`/`object-src`, and the meta CSP carries only fetch directives plus hashes. The two policies don't overlap, so neither weakens nor blocks the other; `frame-ancestors` can only live in the header.
3. **Negotiation** matches §6: valid cookie first; `Accept-Language` by q-value with primary subtag only; ties go to header order (strict `>`); q=0, malformed, or out-of-range q is ignored; English is the default.
4. **Emulator fidelity:** good for what we rely on. `auto-trailing-slash` (extensionless `.html`, `/x.html`→`/x`, `/index.html`→`/`, `/x/`→`/x` for file pages), nearest-404 walk-up, `_headers` on asset responses only (Worker responses are untouched; ASSETS-binding responses do get them, see follow-ups), join-with-`, `, required content types, decode-then-reject traversal plus a `resolve` containment check. It refuses unsupported `wrangler.jsonc` values instead of guessing, which is right.
5. **Declared decisions:** all accepted. `ASSETS.fetch('/')` is sound (`/index.html` would be redirected to `/` by `auto-trailing-slash` and loop through the Worker; same file). `allowBuilds` false is needed, and the dry-run proves esbuild works without its postinstall. The `node -e` env setters avoid a `cross-env` dependency and work under `cmd`. The `ROOT_HEADERS`/`SET_LANGUAGE_HEADERS` exports strengthen the single source. 405 for other methods is sensible. Excluding tests from `worker/tsconfig.json` is needed (workers-types conflicts with DOM/Node), but see R1-03.
