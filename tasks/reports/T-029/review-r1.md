**CR-2 check.** With no `timeoutMs`, `AbortSignal.timeout(REQUEST_TIMEOUT_MS)` behaves the same as the old `setTimeout` + `abort`. It still covers the body read, and an expired timeout (`TimeoutError`) falls into the same `catch`, so it maps to `network`. Not clearing the timer is harmless. NFR-10 (the latest 2 Safari versions) supports `AbortSignal.timeout`. The only callers today are guestbook ones. On `task/T-030-contact-ui`, the contact and phone code passes no `timeoutMs`, has no fake-timer timeout tests, and merges cleanly with this branch. The new tests are meaningful: the default value and the 8 s guestbook value are asserted via `vi.spyOn(AbortSignal, 'timeout')`, and a real 20 ms timeout maps to `network`. That last test uses a real timer, but its outcome is deterministic.

**CR-1 check.** The `--guestbook-*`, `--swatch-*` and `-min-h` names fit the existing per-area groups (`--project-*`, `--skill-*`, `--control-min-h`). One naming nit is R1-03.
