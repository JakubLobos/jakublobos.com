**Declared deviations, checked against `posthog-js@1.438.21`:**

1. `opt_out_capturing_by_default: true` is sound. `ConsentManager.isRejected()` is `DENIED || (PENDING && opt_out_capturing_by_default)`, so `_inCookielessMode()` and `is_capturing()` are both true. `_is_persistence_disabled()` is true (opted out under `on_reject`), and `__ph_opt_in_out_*` is never written. Confirmed in the browser: cookieless events, nothing stored. `loaded` runs synchronously before the initial pageview's `setTimeout`, so a first-time "Accept" sends no cookieless pageview first. For a stored opt-in, `apply()` calls `opt_out_capturing()`, which clears persistence and enters cookieless mode, so the self-healing path works.
2. `advanced_disable_flags: true` is fine. The only PostHog host contacted is `eu.i.posthog.com`, and the `$cookieless_mode` property is set on the client, so no remote config is needed.
3. `scripts/consent-store.ts`: accepted (see Scope).

## Notes for orchestrator

- **`guestbook.smoke` flake (not T-032).** At failure the page showed the API's `empty` state ("No marks yet"), so no approved row existed. The failure is on the server (review worker or approval timing under suite load), not in the client. The consent script never touches the API or `<last-visitor>`, and without consent it loads only the 1.7 KB adapter chunks on idle. The test passed alone and in a full chromium-desktop re-run that included `consent.spec`. This is pre-existing T-029/T-017 flakiness; backlog an investigation of the review worker's in-flight-pass race (`review-worker.ts`) or a longer `toPass` window.
- **CR-1 / CR-2 verified.** Neither weakens anything. The CSP is identical to `main` when the IDs are empty, and the only wildcards are `*.google-analytics.com` and `*.analytics.google.com`.
- **Doc drift.** `docs/security.md` §5 lists `connect-src … https://*.google.com` and omits `https://*.analytics.google.com`. The implementation follows Google's current GA4 list, which is tighter. Update §5. Owner note: keep **Google Signals off** in the GA4 property, or hits to `*.google.com`/doubleclick will be CSP-blocked.
- **Copy (owner, D-22).** "Nothing is sold or shared" stands while "Accept" sends data to Google (US) and PostHog as processors. "Shared" is arguably inaccurate; consider "Nothing is sold or used for advertising", which matches the privacy page. PL drafts need owner review.
- **Leftovers, by design:**
  - After a withdrawal, `__ph_opt_in_out_<key>=0` stays in localStorage. It is a consent flag, not an identifier, and the privacy page's "PostHog keys … set when you press Accept" row covers it.
  - The click on "Only essential" during a withdrawal is itself autocaptured under the consented identity, because PostHog listens in the capture phase. Acceptable.
- `common.cookieNotice` (T-023) is now unused. Remove it in a follow-up; `common.ts` was not in this task's allowed files.
