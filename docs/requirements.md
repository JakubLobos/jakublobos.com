# Requirements

Status: **Baseline v1** (2026-10-25). Requirement IDs are stable; tasks reference them.
Sources: the owner's brief, `docs/design/design.html` (primary visual source of truth), and owner answers recorded in [`decisions/open-questions.md`](decisions/open-questions.md).

Legend: **[D]** is in the design. **[+]** is an addition not in the design (approved or pending, see the decision ID). **[B]** comes from the brief.

## 1. Product summary

A single-page, bilingual (EN/PL) personal portfolio for Jakub Łobos, a frontend developer. It has a playful hand-drawn visual identity: doodle display font, paint drips, a mascot, and "pressable" buttons with hard shadows. Two interactive backend features:

1. **Guestbook** ("I love connecting people through the power of frontend"). Visitors leave a short message with a paint colour. Messages are moderated automatically before anyone else can see them. The latest approved message greets the next visitor.
2. **Contact form.** Name, email, and message, delivered to the owner by email (Resend).

### Backend

| ID    | Requirement                                                                                                                                                                                                                                                              | Src |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --- |
| FR-40 | `POST /api/guestbook` accepts a message and paint and returns `202` once it is the single pending message awaiting review. See [`api.md`](api.md).                                                                                                                       | B   |
| FR-41 | No message is publicly visible until **all** review layers explicitly pass: local rules, OpenAI moderation (threshold 0.2), and an LLM suitability check that protects the owner's professional image. Any failure, timeout, or invalid response never publishes (D-06). | B   |
| FR-42 | Each review provider (moderation, suitability) is isolated behind an interface with a deterministic fake for development and tests; fakes are refused in production.                                                                                                     | B   |
| FR-43 | **Newest wins:** at most one pending message exists. A new submission supersedes older unreviewed ones, and only the newest pending message is reviewed or retried (with backoff; it expires after 24 h) (D-05).                                                         | B   |
| FR-44 | Retention: the guestbook table never holds more than **100** messages (pending + approved). Inserting evicts the oldest approved messages. Rejected, superseded, and expired messages are not stored. Approved messages form a **private archive** (D-17).               | B   |
| FR-45 | `GET /api/guestbook/latest` returns only the newest approved message, or `null`. It is the only public read of guestbook data.                                                                                                                                           | B   |
| FR-46 | Duplicate submissions (same client request ID, or same normalized text as a stored message) are idempotent and never create a second row.                                                                                                                                | B   |
| FR-47 | `POST /api/contact` validates and emails the message to the owner through a `Mailer` interface (Resend HTTPS API in production, console in development; SMTP is blocked on Railway Hobby). Contact messages are not stored (D-04).                                       | B   |
| FR-48 | Admin CLI to list, export (JSON/CSV archive), and delete approved messages and purge pending ones (takedown path and archive access).                                                                                                                                    | +   |
| FR-49 | `GET /api/health` reports liveness and DB readiness for the hosting platform.                                                                                                                                                                                            | +   |
| FR-50 | `POST /api/contact/phone` returns the owner's phone number only after successful server-side Cloudflare Turnstile verification. The number exists only in the API environment, never in the repo or static assets (ADR-0015).                                            | +   |

## 4. Out of scope (v1)

- Dark mode (the design only defines a light scheme with `color-scheme: light`).
- An admin web UI (the CLI covers takedowns and archive export), a CMS, a blog, a **public** archive or list of guestbook messages (D-17: private only), and human pre-moderation.
- Horizontal scaling or multiple server instances.
- Storing contact-form submissions.
- Translating visitor messages.
