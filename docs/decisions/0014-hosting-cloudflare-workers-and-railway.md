# ADR-0014: Hosting: Cloudflare Workers static assets (site) + Railway (API)

- **Status:** Accepted · **Date:** 2026-10-25 · **Supersedes:** the hosting part of ADR-0003 · **Related:** D-14, FR-02…FR-05, NFR-03, NFR-07, NFR-12

## Context

The owner chose the domain `jakublobos.com`, proposed "Cloudflare Pages for frontend, Railway for backend", and asked for easy hosting. Verified facts (2026-10-25):

- **Cloudflare:** the Pages docs say Workers "supports most Pages use cases and offers a broader feature set" and "Start new projects with Workers". With Workers static assets, "requests to static assets are free and unlimited". A Worker script runs only for paths listed in `assets.run_worker_first` (glob patterns, `!` negation). `not_found_handling: "404-page"` serves the **nearest** `404.html` with status 404. The default `html_handling: "auto-trailing-slash"` serves `foo.html` at `/foo`. A `_headers` file applies to static asset responses but **not** to responses generated by Worker code.
- **Railway:** Hobby is $5/month including $5 of usage. Volumes: 5 GB on Hobby, "Replicas cannot be used with volumes", a short downtime on redeploy, and manual and automated volume backups. Outbound **SMTP is blocked** on Free/Trial/Hobby (staff answers linking to the outbound-networking docs). For the client IP, the docs list `X-Real-IP`; staff state the edge overwrites `X-Real-IP` and `X-Forwarded-*`, but the hop count and proxy CIDRs aren't a published contract.

## Decision

| Concern                   | Decision                                                                                                                                                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Site                      | Astro static build (`output: 'static'`, no adapter) deployed as a **Cloudflare Worker with static assets** on `jakublobos.com` (and `www` → apex redirect via a Cloudflare redirect rule). `wrangler.jsonc` lives in `apps/web`. |
| Request-time logic        | A tiny Worker (`apps/web/worker/`) runs **only** for `/` (language negotiation) and `/set-language` (explicit switch). `run_worker_first: ["/", "/set-language"]`. Every other request is a free static asset.                   |
| Headers                   | One TypeScript source of truth (`apps/web/security-headers.ts`). An Astro integration writes `dist/_headers` from it at build time, and the Worker applies the same headers to its own responses.                                |
| 404s                      | `not_found_handling: "404-page"`, so `/pl/...` misses get `pl/404.html` and others get `404.html`.                                                                                                                               |
| API                       | Express 5 on **Railway** (Hobby), Dockerfile build, custom domain **`api.jakublobos.com`** (DNS-only CNAME to Railway; Railway issues TLS), one replica, volume mounted at `/data` for SQLite.                                   |
| Cross-origin              | The browser calls `https://api.jakublobos.com`. The API answers CORS only for an allowlist (`https://jakublobos.com` plus dev/test origins). No cookies are involved.                                                            |
| Client IP (rate limiting) | `CLIENT_IP_SOURCE=x-real-ip` on Railway: read `X-Real-IP`, validate it with `net.isIP`, fall back to the socket address. Express `trust proxy` is not used for this.                                                             |
| Email                     | Resend HTTPS API (SMTP is blocked on Railway Hobby); see ADR-0010.                                                                                                                                                               |

## Alternatives considered

| Option                                                            | Why not                                                                                                                                                                                                           |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cloudflare **Pages** (+ Pages Functions)                          | Still works, but Cloudflare steers new projects to Workers; Workers static assets offers the same free static hosting with finer routing control (`run_worker_first`)                                             |
| Single Node service on Railway serving site + API (previous plan) | Simpler (same origin, no CORS), but the whole site goes down during Railway redeploys or outages, and there's no global CDN for HTML. A static site on Cloudflare stays up even when the API doesn't.             |
| Proxy `/api/*` through the Worker (same origin)                   | Every API call becomes a Worker invocation plus an extra hop; the client IP passes through Cloudflare first, which complicates rate limiting. CORS on a sibling subdomain is simpler.                             |
| Orange-cloud (proxied) `api.jakublobos.com`                       | Adds Cloudflare in front of Railway; the client IP then depends on `CF-Connecting-IP` handling at Railway's edge (only for Cloudflare IPv4 per staff). Keep it DNS-only unless DDoS protection becomes necessary. |
| Fly.io / VPS                                                      | Fine, but the owner asked for easy hosting, and Railway's volume + Dockerfile + GitHub deploys cover it                                                                                                           |

## Consequences

- **Costs:** Cloudflare free (static + under 100k Worker requests/day); Railway Hobby about $5/month (a small Node service fits the included usage; verify on the dashboard after launch); Resend free; OpenAI under $0.05/month after a $5 credit purchase; PostHog and GA4 free tiers.
- The site stays available when the API is down. The guestbook and contact form show their error states (D-12, D-13).
- Two deployables: Cloudflare (`wrangler deploy` from CI) and Railway (deploys from GitHub). The API base URL is a build-time variable (`PUBLIC_API_BASE_URL`).
- The single-instance assumption (SQLite, in-memory rate limits, in-process worker) matches Railway's "no replicas with volumes" rule.
- **Risk:** Railway's `X-Real-IP` behaviour is documented but not a versioned contract. Mitigation: global caps don't depend on IPs, and the go-live checklist verifies observed IPs (`docs/operations.md`).
